A value when you need it. An expiry when you don’t.

from kuttidb import KuttiDBClient

with KuttiDBClient(port=7379) as db:
    db.queue_declare("reports", durable=True)
    db.queue_publish("reports", b"report:42")
    job = db.queue_consume("reports", visibility=30)
    if job:
        print(job["value"])
        db.queue_ack("reports", job["id"])

Acknowledge after processing. Unfinished work can be redelivered.

from kuttidb import KuttiDBClient

with KuttiDBClient(port=7379) as db:
    db.stream_declare("events", partitions=1)
    db.stream_append("events", b"report.ready")
    history = db.stream_fetch(
        "events", partition=0, offset=0
    )
    print(history)

Reading doesn’t remove an event. Come back to the same offset.

Install the client, then connect to a server on port 7379. Save as app.py and run with python3 app.py.

SMALL BY DESIGN. CLEAR ABOUT THE EDGES.

A single server.
On purpose.

A good fit for

Small and midsize SaaS teams running on one server. Local processes can use shared memory; remote clients use the native network protocol.

An optional authenticated Management API and self-hosted web console cover day-to-day operations.

Meet the management API ↗

Know before you deploy

Beta software. No replication yet. Durable delivery is at-least-once. Evictable cache entries can be lost by policy.

KuttiDB speaks its own protocol; it isn’t a drop-in Redis, RabbitMQ, or Kafka replacement.
