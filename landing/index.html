The event cache that
keeps its promises.

KuttiDB is a lightweight, crash-recoverable event cache with durable queues, exchanges, streams, and atomic cache-plus-event commits — in one binary.

No JVM. No Erlang. No external dependencies for a plaintext build. Zero-copy between local processes, network-accessible across machines.

One binary, four engines

It started as a cache. Then it grew
the primitives you usually bolt on next to one.

Durable messaging, routing, and replay — recoverable after a crash, observable over a single authenticated Management API. No sidecars, no brokers to babysit.

Cache engine

In-memory key/value store with TTL, batching, pipelining, and bounded memory with eviction. CRC-checked WAL and snapshots, plus an optional shared-memory embedded mode with ASLR-safe offset-based regions.

Durable queues

Publish confirms, manual ACK/NACK, requeue, visibility timeouts, prefetch, dead-letter queues, retry delays, message expiry, bounded depth — and crash recovery. At-least-once delivery, honestly labeled.

Exchanges & routing

Direct, fanout, and topic routing in front of queues. An unnamed default exchange, alternate-exchange routing, explicit unroutable reporting, and durable bindings.

Streams

Durable, partitioned append logs with keyed partition choice, replay, retention controls, persisted consumer offsets, and leased consumer-group assignment.

Anti-cache-stampede

Native single-flight with leased claims, bounded waits, and negative caching — plus stale-while-revalidate and refresh-ahead. A hot key never melts your database.

Management API & web console

An authenticated, audited, SSE-capable HTTP admin surface — disabled by default, refuses to start unsafely — and a self-hosted React console for dashboards and day-two operations.

The hard part, solved

Cache and messaging,
committed together.

put_and_publish, put_and_enqueue, delete_and_publish, and conditional update_and_emit commit a cache mutation and a delivery under one durable commit id.

  • After recovery, both sides exist or neither does — no phantom events, no lost updates.
  • One acknowledgement point, documented in docs/design/DURABILITY.md, not vibes.
  • Enforced by crash-recovery tests in the standard suite.
cache mutation→ delivery→ one durable commit id→ recover: all-or-nothing

commit_id = db.put_and_publish(

Numbers are evidence, not marketing

Fast enough to be boring.

Every headline number is reproducible with a make target, gated in CI — a regression greater than 10% is release-blocking. These are recorded runs, not guarantees on your hardware.

  • Durable publish/consume/ACK steady state measured as retained depth grows 5k → 20k.
  • Stream append measured as history grows 10k → 100k records across 8 partitions.
  • TSAN builds, fuzz suites, and crash-recovery tests keep the fast path honest.

python — the full v1.8 surface in one pass
from kuttidb import KuttiDBClient

with KuttiDBClient(port=7379) as db:
    db.health()                                   # every engine writable?
    db.put("greeting", b"hello", ttl=60)          # TTL in seconds
    db.put_many([("a", b"1"), ("b", b"2")])       # one round trip

    db.queue_declare("jobs", durable=True, max_depth=100)
    db.queue_publish("jobs", b"payload")
    job = db.queue_consume("jobs", visibility=30)
    db.queue_ack("jobs", job["id"])

    db.exchange_declare("events", type="topic", durable=True)
    db.exchange_bind("events", "jobs", "order.*")
    routes = db.exchange_publish("events", "order.new", b"event")

    # one durable commit: cache write + message delivery
    r = db.put_and_publish("k", b"v", exchange="events", routing_key="order.new")
    assert r["tx_id"] > 0 and r["routed"] == routes

    # anti-stampede loading and stale-while-revalidate
    db.get_or_load("hot", lambda: b"expensive", ttl=60)
    db.put_swr("k", b"fresh", ttl=30, stale_for=60)
    r = db.get_or_refresh("k", lease=5)           # value / stale / refresh

    db.stream_declare("orders", partitions=2)
    p = db.stream_append("orders", b"record", key=b"user-1")
    db.stream_commit("orders", "workers", p["partition"], p["offset"])

with KuttiDBClient.managed(data_dir="./data", idle_timeout=60) as local:
    local.put("k", b"v")                          # private local server

Single connection per instance — worker threads dial their own clients. Misses return None, never exceptions.

node — the full v1.8 surface in one pass
const { Client } = require("@kuttidb/client");

const db = new Client({ port: 7379, poolSize: 4 });
await db.health();
await db.put("greeting", Buffer.from("hello"), { ttl: 60 });
await db.putMany([["a", "1"], ["b", "2"]]);

await db.queueDeclare("jobs", { durable: true, maxDepth: 100 });
await db.queuePublish("jobs", Buffer.from("payload"));
const msg = await db.queueConsume("jobs", { visibility: 30 });
await db.queueAck("jobs", msg.id);

await db.exchangeDeclare("events", { type: "topic", durable: true });
await db.exchangeBind("events", "jobs", "order.*");
const routes = await db.exchangePublish("events", "order.new",
                                        Buffer.from("event"));

// one durable commit: cache write + message delivery
await db.putAndPublish("k", Buffer.from("v"),
                       { exchange: "events", routingKey: "order.new" });

// anti-stampede loading and stale-while-revalidate
await db.getOrLoad("hot", async () => Buffer.from("expensive"),
                   { ttl: 60 });
await db.putSwr("k", Buffer.from("fresh"),
                { ttl: 30, staleFor: 60, refreshAfter: null });
await db.getOrRefresh("k", { lease: 5 });

await db.streamDeclare("orders", { partitions: 2 });
const pos = await db.streamAppend("orders",
                                  Buffer.from("record"), { key: "user-1" });
await db.streamCommit("orders", "workers", pos.partition, pos.offset);

Async/await throughout; the pool pipelines requests so a slow consumer never blocks cache traffic.

import kuttidb "github.com/kuttidb/kuttidb/clients/go"

c, err := kuttidb.New("127.0.0.1:7379", 4) // pooled
if err != nil { log.Fatal(err) }
defer c.Close()
_, _ = c.Health()
_ = c.Put("greeting", []byte("hello"))
_ = c.PutWithTTL("brief", []byte("v"), 30*time.Second)
_ = c.PutMany(map[string][]byte{"a": []byte("1")})

_ = c.QueueDeclare("jobs", kuttidb.QueueOptions{Durable: true, MaxDepth: 100})
_, _ = c.QueuePublish("jobs", []byte("payload"), 0)
d, _ := c.QueueConsume("jobs", 30*time.Second)
_, _ = c.QueueAck("jobs", d.DeliveryTag)

_ = c.ExchangeDeclare("events", kuttidb.ExchangeOptions{Type: kuttidb.ExchangeTopic, Durable: true})
_ = c.ExchangeBind("events", "jobs", "order.*")
routes, _ := c.ExchangePublish("events", "order.new", []byte("event"), 0)

// one durable commit: cache write + message delivery
r, _ := c.PutAndEnqueue("k", []byte("v"), "jobs", 0)
_ = r.TransactionID

// anti-stampede loading and stale-while-revalidate
_, _ = c.GetOrLoad("hot", func() ([]byte, error) { return []byte("x"), nil },
                   30*time.Second, 5*time.Second, 10*time.Second)
_ = c.PutSWR("k", []byte("fresh"), 30*time.Second, time.Minute, 0)
_, _ = c.GetOrRefresh("k", 5*time.Second)

_ = c.StreamDeclare("orders", kuttidb.StreamOptions{Partitions: 2})
pos, _ := c.StreamAppend("orders", []byte("record"), []byte("user-1"), nil)
_ = c.StreamCommit("orders", "workers", uint32(pos.Partition), pos.Offset)

java — the full v1.8 surface in one pass
import io.github.kuttidb.client.*;
import java.nio.charset.StandardCharsets;
import java.util.Map;

try (KuttiDBClient db = new KuttiDBClient("127.0.0.1", 7379)) {
    db.health();
    db.put("greeting", "hello".getBytes(StandardCharsets.UTF_8), 60_000);
    db.putMany(Map.of("a", "1".getBytes(StandardCharsets.UTF_8)));

    db.queueDeclare("jobs",
            new KuttiDBClient.QueueOptions().durable(true).maxDepth(100));
    db.queuePublish("jobs", "payload".getBytes(StandardCharsets.UTF_8));
    KuttiDBClient.QueueDelivery d = db.queueConsume("jobs", 30_000);
    db.queueAck("jobs", d.deliveryTag);

    db.exchangeDeclare("events", new KuttiDBClient.ExchangeOptions()
            .type(KuttiDBClient.ExchangeType.TOPIC).durable(true));
    db.exchangeBind("events", "jobs", "order.*");
    db.exchangePublish("events", "order.new",
            "event".getBytes(StandardCharsets.UTF_8));

    // one durable commit: cache write + message delivery
    KuttiDBClient.AtomicResult r = db.putAndEnqueue("k",
            "v".getBytes(StandardCharsets.UTF_8), "jobs", 0);
    assert r.transactionId > 0;

    // anti-stampede loading and stale-while-revalidate
    byte[] v = db.getOrLoad("hot",
            () -> "expensive".getBytes(StandardCharsets.UTF_8),
            30_000, 5_000, 10_000);
    db.putSWR("k", "fresh".getBytes(StandardCharsets.UTF_8),
              30_000, 60_000, 0);
    db.getOrRefresh("k", 5_000);

    db.streamDeclare("orders", new KuttiDBClient.StreamOptions().partitions(2));
    KuttiDBClient.StreamPosition p = db.streamAppend("orders",
            "record".getBytes(StandardCharsets.UTF_8),
            "user-1".getBytes(StandardCharsets.UTF_8), null);
    db.streamCommit("orders", "workers", (int) p.partition, p.offset);
}

rust — the full v1.8 surface in one pass
use std::time::Duration;
use kuttidb::{Client, ExchangeOptions, ExchangeType, QueueOptions, StreamOptions};

let mut c = Client::connect("127.0.0.1:7379")?;
c.health()?;
c.put("greeting", b"hello", Some(Duration::from_secs(60)))?;
c.put_many(&[("a", b"1".as_slice()), ("b", b"2")])?;

c.queue_declare("jobs", QueueOptions {
    durable: true, max_depth: 100, ..Default::default()
})?;
c.queue_publish("jobs", b"payload", None)?;
let d = c.queue_consume("jobs", Duration::from_secs(30))?.unwrap();
c.queue_ack("jobs", d.delivery_tag)?;

c.exchange_declare("events", ExchangeOptions {
    exchange_type: ExchangeType::Topic, ..Default::default()
})?;
c.exchange_bind("events", "jobs", "order.*")?;
c.exchange_publish("events", "order.new", b"event", None)?;

// one durable commit: cache write + message delivery
let r = c.put_and_enqueue("k", b"v", "jobs", None)?;
assert!(r.transaction_id > 0);

// anti-stampede loading and stale-while-revalidate
let _ = c.get_or_load("hot", || Ok(Some(b"expensive".to_vec())),
                      Some(Duration::from_secs(30)),
                      Duration::from_secs(5), Duration::from_secs(10))?;
c.put_swr("k", b"fresh", Duration::from_secs(30),
          Duration::from_secs(60), None)?;
let _ = c.get_or_refresh("k", Duration::from_secs(5))?;

c.stream_declare("orders", StreamOptions {
    partitions: 2, ..Default::default()
})?;
let pos = c.stream_append("orders", b"record", b"user-1", None)?;
c.stream_commit("orders", "workers", pos.partition as u32, pos.offset)?;

What KuttiDB is not

Honesty about limits is part of the design.

“Numbers are evidence, not marketing — and no exactly-once claim anywhere.”
  • Not Redis, RabbitMQ, or Kafka — and it speaks none of their wire protocols. The native protocol comes first; compatibility adapters are a later, separate milestone.
  • No “no data loss” guarantee. Evictable cache entries may be lost by policy. Acknowledged durable queue messages survive crashes and clean restarts on a healthy single node — but one node can’t protect against disk or machine loss. Replication is on the roadmap, not in the binary.
  • Windows is in progress — IOCP, named pipes, and mapping work are tracked on the roadmap.
